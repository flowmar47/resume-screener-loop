# Gap Scorecard

Use in Phase 1 after JD extraction and profile synthesis. Show the user this table **before** drafting. It drives Phase 1.5 discovery and sets honest expectations for the screener pass.

## Build the scorecard

For each **must-have** from the JD (required qualifications, hard filters):

| JD requirement | Profile evidence | Status | Notes |
|----------------|------------------|--------|-------|
| e.g. 5+ years technical customer-facing | PM 2017–present + 18mo consulting | ✅ Strong | Meets via combined roles |
| e.g. Large-format workshops | Internal training only, not named | 🟡 Adjacent | Ask in discovery |
| e.g. Public technical writing | Personal site only, no blog/Cookbook | ❌ Gap | Flag in cover note |

**Status definitions:**

| Status | Meaning | Next step |
|--------|---------|-----------|
| ✅ **Strong** | Explicit project, metric, or achievement in profile | Use in lead role bullets |
| 🟡 **Adjacent** | Close but not exact; reframe may work | Phase 1.5: 1–2 questions |
| ❌ **No evidence** | Nothing in profile supports this | Do not claim; flag stretch |

For **preferred** qualifications, add a second table or mark as nice-to-have. Missing preferred items lower rank but are not screen-killers unless the field is competitive.

## Fit tier mapping

| Scorecard pattern | Fit tier |
|-------------------|----------|
| All must-haves ✅ or defensible 🟡 with bridge | Strong or moderate-strong |
| One must-have 🟡 with strong bridge elsewhere | Moderate |
| One must-have ❌ with no substitute | Weak |
| Multiple must-haves ❌ | Very weak |

## Present to the user

Template:

```markdown
## Gap scorecard: [Role] at [Company]

**Fit tier:** [tier] — [one sentence why]

### Must-haves
| Requirement | Your evidence | Status |
|-------------|---------------|--------|
| ... | ... | ✅ / 🟡 / ❌ |

### Preferred (summary)
- ✅ [met items]
- 🟡 / ❌ [gaps worth naming]

### Recommended before drafting
- [Discovery questions for 🟡 items]
- [Honest flags for ❌ items]

Proceed with tailoring? (Y / adjust inputs / pick different role)
```

## Rules

- **Tie every row to the JD**, not generic resume advice.
- **Do not upgrade ❌ to 🟡** without new user-provided evidence.
- **Distinguish structural vs content gaps.** Missing keyword in an existing bullet is content; missing entire experience is discovery or honest gap.
- In **batch mode**, add a column or note: "appears in N of M jobs" for leverage (see `batch-workflow.md`).

## After discovery (Phase 1.5)

Re-run the scorecard. Update statuses only when the user supplies defensible facts. Re-state fit tier if it changed.
